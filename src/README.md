# Эмулятор контроллера мотора Fardriver (новый протокол) на Arduino Nano

Ведёт себя на линии как настоящий контроллер Fardriver с «новым» протоколом:
после включения шлёт `AT+VERSION`, на рукопожатие `AA 13 EC 07 01 F1 A2 5D` отвечает
непрерывным потоком 16-байтных пакетов `AA 80 … AA B6` (55 штук по кругу, ~28 мс каждый).
Данные берутся из физической модели «батарея + мотор-колесо + контроллер + мотоцикл», поэтому
скорость, ток, напряжение, температуры и ошибки меняются согласованно и «естественно».

## Подключение

| Nano | Куда | Примечание |
|------|------|-----------|
| D6 (RX) | TX опрашивающей платы (UART мотора, 19200 8N1) | |
| D5 (TX) | RX опрашивающей платы | Nano выдаёт **5 В**. Если вывод RX платы не 5V-tolerant (в даташите STM32 — не «FT»), ставьте делитель 1 кОм / 2 кОм |
| GND | GND | |
| D3 | кнопка → GND | короткое — следующий режим, долгое (>0.8 с) — перезапуск режима |
| D13 | встроенный LED | мигает номером режима |

USB (115200): статус раз в секунду и команды: `n`/`p` — след./пред. режим, `r` — перезапуск,
`<номер>`+Enter — выбрать режим, `l` — список, `x` — hex-дамп всего, что уходит в линию, `h` — справка.

Смена или перезапуск режима = «выключили и включили контроллер»: 0.4 с тишины, затем `AT+VERSION`,
плате нужно заново пройти рукопожатие.

## Файлы

- `config.h` — **все настройки**: тайминги протокола, сомнительные масштабы (RPM, газ), батарея, мотор, колесо, лимиты контроллера, пороги защит, пины.
- `modes.cpp` — **режимы** и профили «водителя» (газ, тормоз, передача, уклон, толкание).
- `motor_model.*` — модель: OCV и внутреннее сопротивление батареи, противо-ЭДС, FOC-токи Id/Iq, ослабление поля, ограничения фазного/линейного тока, рекуперация, динамика мотоцикла (масса, качение, аэродинамика, уклон), датчики Холла, нагрев мотора и контроллера, защиты с задержкой и гистерезисом. «Истинное» состояние отделено от «измеренного» (шумы, округления).
- `fd_packet.*` — сборка пакетов по адресам слов из ПО Fardriver (не по вашим структурам), CRC, разбор команд хоста, шаблон всех 55 пакетов из реального дампа.
- `emulator.*` — связка модели, режимов и протокола: состояния линии, расписание пакетов, неисправности канала. От железа не зависит.
- `MotorFardriverEmulator.ino` — только ввод/вывод: SoftwareSerial, кнопка, LED, консоль.
- `tests/` — проверка на ПК вашим драйвером (см. ниже); `test_output.txt` — лог с исправленным драйвером, `test_output_original_driver.txt` — с исходным.
- `driver_fix/` — исправленный драйвер: патч (`git am`) и готовые файлы.

Размер (avr-gcc 7.3 из Arduino IDE / 8.1): ~24 КБ flash, ~670 Б статической RAM.
Не собирайте avr-gcc 14 — у него регрессия в коде с float, прошивка раздувается до ~40 КБ.

## Режимы

| # | Режим | Что видно |
|---|-------|-----------|
| 1 | Стоянка, нейтраль | как в дампе: 0 об/мин, N, ошибок нет |
| 2 | Разгон и крейсер 50 км/ч | разгон до ~160 А, крейсер 11–21 А (неровности дороги), торможение с рекуперацией (ток < 0) |
| 3 | Город | разгоны до 30–60 км/ч (каждый цикл разный), накат, рекуперация, стоянки |
| 4 | Задний ход | передача R, движение назад |
| 5 | Передача Low, подъём 6 % | Low (код 3), ограничение оборотов ~50 % |
| 6 | Толкают руками | N вперёд/назад, D назад (откат против передачи), ток 0 |
| 7 | Максимальная скорость | до ~107 км/ч, ослабление поля: D0 бит6 (WEAK), Id < 0 |
| 8 | Перегрев контроллера (×10) | Tc → 95 °C, снижение тока, ошибка 0x0080, остывание, повтор |
| 9 | Перегрев мотора (×10) | Tm → 120 °C, ошибка 0x0040; при долгом подъёме доходит и до 0x0080 |
| 10 | Батарея разряжена | урезание тока у 60 В, отсечка 0x0010 (бит15 в 0xB3 = 0 — «Under Voltage»), повтор |
| 11 | Полная батарея, спуск | рекуперация поднимает шину до >88 В: 0x0010 + бит15 в 0xB3 = 1 («Over Voltage») |
| 12 | Газ зажат при включении | ошибка педали 0x0002, мотор не крутит, пока газ не отпустят |
| 13 | Обрыв датчика Холла | Холлы = 111, ошибка 0x0001, мотор не крутит (можно толкать) |
| 14 | Сбой: нет ответа | контроллер молчит полностью |
| 15 | Сбой: нет рукопожатия | вечный `AT+VERSION`, запросы игнорируются |
| 16 | Сбой: битая CRC | каждый 3-й пакет с неверной CRC |
| 17 | Сбой: склеенные/обрезанные | иногда 32 байта без паузы, иногда 11 байт |
| 18 | Сбой: пропадание | каждые 15 с молчит 3 с, потом продолжает поток |
| 19 | Сбой: перезагрузка | каждые 20 с: 1.5 с тишины, `AT+VERSION`, нужно новое рукопожатие |

`×N` — ускорение модельного времени для нагрева, батареи и пробега (динамика — в реальном времени).
Тормоз в любом режиме поднимает бит 15 ошибок (гипотеза, см. ниже).

## Как добавить режим

В `modes.cpp`:

```cpp
static const char N_WINTER[] PROGMEM = "Зима, город";
...
//   name      profile    p1     p2    p3   soc amb  Tmot  Tctl speed faults      dev
{ N_WINTER, prof_city, 40.0f, 0.6f, 0,   60, -15, -128, -128, 1,  FAULT_NONE, DEV_NONE },
```

Свой характер езды — функция `void prof_xxx(const ModeDesc &m, float t, const MotorModel &mm, DriverInput &in)`:
по времени `t` (с) и состоянию `mm` (скорость, ошибки…) выставляет `in.throttle` 0..1, `in.brake`,
`in.gear` (`GEAR_N/D/R/LOW`), `in.grade` (уклон), `in.push` (толкают, Н), `in.regen` (множитель рекуперации).
Ограничения токов, защиты, нагрев и всё содержимое пакетов модель делает сама.
Новая неисправность канала — флаг `FAULT_*` в `modes.h` и обработка в `Emulator::poll()`.

## Протокол (что эмулируется и откуда это известно)

- UART 19200 8N1 (Saleae: 520 мкс на байт). Пакет `AA A1 D0…D11 CRClo CRChi`, слова little-endian.
- CRC-16/MODBUS (полином 0xA001), начальное значение **0x7F3C**, по байтам 0…13, младший байт первым
  (табличный вариант в ПО, начальные `0x3C/0x7F`). Проверено на всех пакетах дампов.
- `A1 = 0x80 | idx`, idx 0…54; каждый пакет — 6 слов «памяти» контроллера с адреса `FD_ADDR_MAP[idx]`
  (таблица `fID → real fID` из ПО). Оперативные блоки 0xE2/0xE8/0xEE повторяются 8 раз за цикл (каждые ~193 мс),
  остальное — 1 раз за цикл (1.548 с).
- До рукопожатия — `AT+VERSION` каждые 68 мс. Команда хоста — 8 байт: `AA cmd ~cmd p1 p2 p3 sum ~sum`,
  `sum` = сумма байт 0…5. Эмулятор проверяет сумму; `cmd 0x13` = подключение/keep-alive, остальные считает, но не исполняет.

| Пакет (адрес) | Поле | Как заполняет эмулятор | Источник |
|---|---|---|---|
| 0x80… (0xE2) D0 | б0-1 передача (0 N, 1 D, 2 R, 3 Low), б2-3 «скорость» (=1), б4 вращение против передачи, б5 движется, б6 WEAK, б7 =1 | модель | дизассемблер, дампы |
| D1 | б0-2 датчики Холла (1-3-2-6-4-5), б3 =1 (иначе ПО пишет «Pass Error») | модель | дизассемблер, дампы |
| D2-3 | ошибки (биты 0…14 по ПО), бит15 — исключён ПО из «есть ошибка», похоже на статус тормоза | модель | дизассемблер |
| D4-5 | ×1/128 — коэффициент модуляции (предположение) | модель | дизассемблер |
| D6-7 | об/мин × `CFG_RPM_RAW_PER_RPM` (настройка контроллера, по умолчанию 4) | модель | дизассемблер, ваши данные |
| D8-9, D10-11 | ×1/16 А, в покое −1…−5 — токи Id, Iq (назначение — предположение) | модель | дизассемблер, дампы |
| 0x81… (0xE8) D0-1 | напряжение ×0.1 В | модель | дизассемблер, дампы |
| D2-3 | второе напряжение (в дампах ±0.4 В от первого) | модель | дампы |
| D4-5 | ток батареи ×0.25 А, со знаком | модель | дизассемблер |
| D6-7, D8-9 | ×1/16 А (здесь — заданные Iq/Id, предположение) | модель | дизассемблер |
| D10-11 | газ (масштаб неизвестен, `CFG_THROTTLE_RAW_*`) | модель | ваш драйвер |
| 0x82… (0xEE) D4-6, D7-9 | 24 бит big-endian, ПО: `√x·125/64` А — фазный ток | модель | дизассемблер |
| 0xB3 (0xD6) D10-11 | температура контроллера, °C | модель | дизассемблер, дампы |
| 0xB3 D4-5 бит15 | 1 — перенапряжение, 0 — недонапряжение (уточняет бит 4 ошибок) | модель | дизассемблер |
| 0xB5 (0xF4) D0-1 | температура мотора, °C | модель | дизассемблер, дампы |
| 0xB6 (0xFA) D0-1, D2-3 | ~2040 — похоже на нули датчиков тока | шум ±1 | дампы, дизассемблер |
| 0x94 D8-9 + 0x98 D10-11 | пробег (мл./ст. слово), ×0.1 км — по заметкам | модель | дизассемблер (склейка), заметки (масштаб) |
| все остальные | параметры, серийный номер и пр. | как в дампе 2024 г. | дамп |

## Сравнение с вашим драйвером (MotorFardriverNew)

Эмулятор повторяет контроллер (по дампам и дизассемблеру ПО Fardriver), а не драйвер. Исправленный драйвер —
в `driver_fix/` (патч к ветке `board_v2.2` и готовые файлы).

### Байт D0 пакета 0x80 (передача и направление)

В обеих версиях ПО (`parser_as_ line1757.c` и `FUN_004396f0.h`, ветка `case 0xe2`) разбор одинаковый — битовые поля:

| бит | смысл |
|---|---|
| 0-1 | передача: 0 N, 1 D, 2 R, 3 Low |
| 2-3 | уровень скорости (переключатель 1/2/3) |
| 4 | колесо вращается *против* направления передачи (R — назад, N/D/Low — вперёд) |
| 5 | 0 — стоит, 1 — вращается |
| 6 | 0 — MTPA, 1 — WEAK (ослабление поля) |
| 7 | в ПО не используется, в дампах всегда 1 |

«Байт пополам» (младший полубайт — передача, старший — код вращения 0/1/2) — это **старый** протокол
(`FUN_004396f0.h`, строки ~170–250). Отсюда и старые `gear : 4` / `roll : 4` и 0x08/0x0A/0x0B: в новом протоколе
в старший полубайт попадают ещё бит 6 (WEAK) и бит 7.

Одна странность ПО: при Low и бите 4 = 1 оно пишет «Forward». Low — передача вперёд, поэтому в исправленном драйвере
это «назад» (откат), как и на D.

### Что было в исходном драйвере и что исправлено

| | Исходный драйвер | Исправленный |
|---|---|---|
| gear/roll | `gear:4`, `roll:4`, roll по 0x08/0x0A/0x0B — направление верно только на R | битовые поля; roll = бит 5 + направление передачи, инвертированное битом 4 |
| ослабление поля | бит 6 → ROLL_UNKNOWN | не влияет |
| бит 15 ошибок | ERROR_CTRL при каждом торможении | авария = `error_flags & 0x7FFF` (`ErrorAlarmMask`); `errors` в common_data — как пришло |
| ERROR_CTRL | гаснет через ~28 мс (следующий `RawRx` ставил NONE) | держится, пока контроллер сообщает аварию |
| ток | `(current * 10U) / 4U` — работает только благодаря 32-битному переполнению | `(int32_t)current * 10 / 4` |
| мощность | `int16_t` переполняется выше 32 767 Вт | считается в `int32_t`, ограничивается |
| скорость | `uint32` × raw rpm переполняется при raw > ~40 000 | 64-битное умножение, `RpmRatio = 4` |
| пробег | не читался | 0x94 D8-9 + 0x98 D10-11 → `common_data.odometer` (0.1 км, масштаб из заметок) |
| структуры | — | `packet_80_t` (Холлы, модуляция, Id/Iq), `packet_81_t` (второе напряжение), `packet_94_t`, `packet_98_t`, `packet_B3_t` (уточнения пере-/недонапряжения и обрыва/КЗ фазы) |
| `MotorManager::Tick()` | падает, если подключён один мотор | пропускает пустой слот |

Прогон на ПК против эмулятора (19 режимов):
- исходный драйвер — путает направление (до 480 кадров на режим), ROLL_UNKNOWN при ослаблении поля, ERROR_CTRL на тормозе, пробег 0;
- исправленный — **всё совпадает с моделью во всех режимах**; ERROR_CTRL появляется только в режимах с настоящей аварией
  (перегревы, напряжение, педаль, Холлы) и держится, пока она есть.

Осталось проверить на мотоцикле: меняется ли бит 15 от ручки тормоза, и масштаб пробега (0.1 км).
Таймаут keep-alive у реального контроллера неизвестен (в заметках 1000 мс, в драйвере 1250 мс).

Нормально отрабатывают обе версии: потеря связи (ERROR_LOST и восстановление), перезагрузка контроллера с новым
рукопожатием, битая CRC (ERROR_CRC, данные не портятся), склеенные/обрезанные пакеты (ERROR_LENGTH).

## Проверка на ПК

```
tests/run_tests.sh <путь к SlaveECU_Motor>            # все режимы
tests/run_tests.sh <путь> -v 7                         # режим 7 подробно (модель и драйвер раз в 3 с)
```

Тест собирает ядро эмулятора g++ вместе с вашими `MotorManager.cpp` и `MotorFardriverNew.h`, моделирует линию
побайтно (19200 бод, кадр по IDLE как `HAL_UARTEx_ReceiveToIdle_IT`, полудуплекс SoftwareSerial) и для каждого режима:
1) разбирает каждый отправленный пакет независимым эталонным разбором (по дизассемблеру) и сверяет с «измерениями»
модели — во всех 19 режимах 0 несовпадений; 2) после разбора драйвером сравнивает `common_data` с моделью.

## Ограничения

- **Полудуплекс SoftwareSerial.** На время передачи пакета приём выключается (`stopListening()` / `listen()`):
  иначе байт хоста посреди пакета запускает прерывание приёма SoftwareSerial (~0.5 мс на байт), передача встаёт,
  и плата по IDLE получает пакет, разрезанный на два (ERROR_LENGTH, а следующий байт после IDLE STM32 может потерять).
  Пока Nano передаёт пакет (8.3 мс из каждых 28 мс), запросы хоста не принимаются, и ~половина
  запросов keep-alive теряется (в тесте: 35 из 77). Реальному контроллеру это не грозит. Поэтому по умолчанию
  `CFG_KEEPALIVE_TIMEOUT_MS 0` (без таймаута); с 3000 мс эмулятор ~раз в 8 с уходит в `AT+VERSION`, и драйвер
  переподключается. Рукопожатие из-за этого иногда проходит со 2-й попытки.
- Не расшифрованные поля отдаются как в дампе покоя; команды записи параметров не исполняются.
- Захваты `.sal` (Logic 2) — недокументированный сжатый формат, удалось декодировать лишь частично; данные «в движении»
  из них не использованы, поэтому масштаб газа, назначение D4-5/D8-11 и поведение бита 4/15 — по дизассемблеру и логике.
